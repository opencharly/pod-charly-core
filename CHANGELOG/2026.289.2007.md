# 2026.289.2007 — fix(skills): move four core skill bodies off the retired `engine.build`, at the source

Agent: charly-dsh

## Summary

**Moves four core skill bodies off the retired `engine.build` — at the SOURCE, not at either of the two
generated levels below it.**

`engine.build` was removed from the contract by the BuildKit cutover (`opencharly/opencharly#481`): the
image builder is BuildKit, which is not a container engine, so it cannot run a container and therefore
cannot be selected like one. Four bodies under `.agents/skills/` still conditioned behaviour on it.

```
$ grep -rn 'engine\.build' .agents/skills/          # before, at 8f6bb8d^
.agents/skills/shell/SKILL.md:165          "When `engine.build` differs from `engine.run`, images are
                                            automatically transferred between engines on demand …"
.agents/skills/service/SKILL.md:137        "When `engine.build=docker`, `charly config` auto-detects if
                                            the image is missing from podman …"
.agents/skills/deploy/SKILL.md:471         (the same sentence)
.agents/skills/charly-doctor/SKILL.md:130  "— `engine.build`, `engine.run`, `secret_backend` settings …"
```

**Three of the four are a MOVED TRIGGER, not a deletion**, and the measurement is why:

```
$ charly settings get engine.build                      ->  podman     (a registered default)
$ grep -rn 'engine.build' in the resolved spec's schema/*.cue
    ->  only `extra_candy_refs`, an unrelated field
```

So `settings get` answers and nothing consumes the answer — the key is **inert, not absent**. And the
behaviour those sentences describe is real: `shell` cites `dispatchBuildEnsure`
(`charly/dispatch_build_ensure.go`), `service`/`deploy` cite `sdk/deploykit/quadlet.go`. **What is
impossible is `engine.build` *differing from* `engine.run`, because it does not exist.** The condition
therefore moves to `engine.run`, which this corpus already states is unaffected:

```
$ marketplace/build/skills/build/SKILL.md:448-450
    **There is no `engine.build`**: the image builder is BuildKit, which is not a container engine —
    it cannot run a container and therefore cannot be selected like one. `engine.run` is unaffected
    and still selectable.
```

**The fourth is a pure deletion**, because a cross-reference list entry has no behaviour to move:
`charly-doctor` listed the key among the settings `charly-core:charly-config` owns, and it no longer
owns it.

The diff is four lines:

| file | before | after |
|---|---|---|
| `.agents/skills/shell/SKILL.md:165` | `When `engine.build` differs from `engine.run`` | `When a build and a run name different engines` |
| `.agents/skills/service/SKILL.md:137` | `When `engine.build=docker`` | `When `engine.run=docker`` |
| `.agents/skills/deploy/SKILL.md:471` | `When `engine.build=docker`` | `When `engine.run=docker`` |
| `.agents/skills/charly-doctor/SKILL.md:130` | `— `engine.build`, `engine.run`, …` | `— `engine.run`, …` |
