mechanical confirmation is the resolving-ref count below, which is byte-identical across the

**On `git diff`'s hunk header.** The `@@ ... @@` suffix on these hunks names a key that looks
structural (e.g. `deploy-skill:`), and it is tempting to read that as proof the ref is a real
dependency entry. It is not: that suffix is git's *context heuristic* — the nearest preceding
line that is less indented and matches its pattern. Inside a block scalar every line is opaque
text, so the heuristic latches onto whatever the prose happens to contain. The two checks above
read the file's actual structure; the hunk header does not.

Anyone can verify independently — the enclosing `key: |` opener and the fence line are quoted
above with their line numbers, so `sed -n '<opener>,<ref>p' charly.yml` shows the whole block.
